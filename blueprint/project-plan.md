# Project Plan

> Generated by `/adopt` from the existing codebase plus a short interview.
> Items marked `> TODO (confirm)` are inferences the user should verify or correct.

## 1. Problem - What problem are we solving?

Nicek Group is a real diversified conglomerate (healthcare, international
exports, auto spare parts, real estate/investments, IT, food & beverage)
operating across the United States and Nigeria. The website exists to
establish credibility with prospective customers and partners across all six
sectors and convert visitors into contacts (phone, email, or the contact
form). It is a marketing/brochure site, not a transactional product.

The repo was scaffolded from an audit of a prior version of the site
(`nicek-audit-report.md`), which found real problems. One is now fixed, one
remains:

- ~~Conflicting contact info across pages~~ - fixed by feature 6: the footer,
  contact page, and all three offices now show the same email and hours.
- The contact form (`src/app/contact/page.tsx`) is a server action
  (`handleContactSubmit`) that only `console.log`s the submission - no email
  is sent and nothing is persisted. Submissions are currently lost. Feature 7
  fixes this.

## 2. Users - Who is this for?

- Prospective customers and partners researching one of the six subsidiary
  sectors (healthcare, exports, autos, investments, tech, food) before
  reaching out.
- People who already know the company and want contact details, office
  locations, or to submit an inquiry.

## 3. Features - What does the MVP need?

Already shipped (see build plan for the checked list):

- Home page with hero, subsidiary grid, and achievement stats.
- About page with mission/vision, journey, company values, testimonials.
- Services overview page plus 6 individual subsidiary detail pages
  (healthcare, exports, autos, investments, tech, food).
- Contact page with office info cards and a contact form (UI only, not wired).
- Global navbar with services dropdown, mobile menu, and light/dark theme
  toggle; global footer with office locations and social links.

Not yet shipped:

- Make the contact form actually deliver submissions by email, with a real
  success/error state, replacing the current `console.log` stub (feature 7).

## 4. Data - What are we storing?

Nothing is persisted - there is no database, and none is planned. All content
(subsidiary list, testimonials, company values, service descriptions, stats)
is hardcoded as TypeScript arrays directly in the page files. Contact form
submissions are emailed, not stored (decided when feature 7 was spec'd - see
Tech below).

## 5. Tech - What stack are we using?

- Next.js 16.2.10 (App Router), React 19.2.4, TypeScript 5, strict mode.
- Tailwind CSS v4 (CSS-first config via `@theme` in `src/app/globals.css`,
  no `tailwind.config.js`).
- shadcn/ui (`style: radix-nova`, `baseColor: neutral`) - currently only
  `button` and `card` components installed - plus `radix-ui`,
  `class-variance-authority`, `tailwind-merge`, `tw-animate-css`.
- `lucide-react` for icons; three custom social icon components
  (Instagram/Facebook/Youtube) live in `src/components/`.
- **Resend** (planned, feature 7) - transactional email so contact form
  submissions actually deliver to the company inbox. Needs a `RESEND_API_KEY`
  env var and, to send convincingly from `@nicekgroup.com`, sender-domain DNS
  records at Namecheap (separate from, but alongside, the Vercel domain
  cutover).
- No database, no ORM, no auth provider.
- No test runner configured.
- No CI (`.github/workflows/` absent).
- Package manager: npm (`package-lock.json` present).
- Git remote: `https://github.com/Ritashsehu/nicek.git` (origin).

## 6. Monetize - How will this make money?

Not applicable in-app. The site itself doesn't transact; it drives leads to
the underlying subsidiary businesses (healthcare services, export/import
deals, auto parts sales, investment partnerships, IT contracts, food &
beverage supply).

## 7. UI/UX - How should this look and feel?

Clean, modern corporate look: zinc-based neutral palette, light mode default
with a working dark mode toggle (persisted to `localStorage`), shadcn/ui Card
components for grids, generous whitespace, gradient hero banners with a
dark overlay image background on interior pages. Consistent per the shadcn
`radix-nova` style already configured.
